# Deviations from the paper's setup

The course report requires a complete table of deviations: every change from the
paper's setup, with the paper's setting, the setting used here and the reason.

| ID | Item | Paper's setting | Setting used here | Reason |
| --- | --- | --- | --- | --- |
| D1 | Labelling | 1,500 defects labelled by two annotators, disagreements resolved by a third senior researcher; Cohen's kappa 0.8–1.0 | The labels released with the dataset are used unchanged | The candidate pool, the annotator assignments and the protocol are not public, and re-labelling 1,500 patches is outside the scope of a course replication. This is the main limitation of the work. |
| D2 | Data collection | Crawlers over Android Security Bulletins, the Linux bug tracker and HarmonyOS trackers; per-system windows 2023.04–2025.06 (Linux), 2023.05–2025.06 (HarmonyOS), 2023.05–2025.12 (Android); 32,249 / 712 / 1,750 initial reports (Table I) | Dashboard snapshot of 2026-11-05, hashed in `data/PROVENANCE.json` | The dashboard is the only public source at full scale. Table I's funnel cannot be rebuilt from the released records and is not verified. |
| D3 | Repaired-code-element percentages (last panel of Table II) | Not stated; `Code Level` is a comma-separated multi-label | A defect counts once for every tag it carries; percentage = count / 500 (so the panel sums above 100 %) | This is the only rule we found that reproduces all 36 printed percentages. |
| D4 | Trigger categories in Figure 4c | Not stated | Categories that are zero for **both** systems of a pair are removed before ranking | Required to reproduce the printed 0.38 for Android–HarmonyOS; keeping the zero gives 0.61. Panels (a) and (b) have no shared zeros, so the rule only affects (c) and the pooled panel (d). |
| D5 | Figure 4d, “overall” | The paper does not say how the overall vector is constructed | Our baseline pools the 21 categories of panels (a)–(c) and applies D4; eight alternative rules are compared in `DISCREPANCIES.md` | No rule reproduces the three printed coefficients; the panel is under-specified. |
| D6 | HarmonyOS severity | Table II reports HarmonyOS `Undecided` 1.20 % | The six HarmonyOS records labelled `Unknown` are mapped to `Undecided` | Gives 6/500 = 1.20 % exactly. Without the mapping the category would not exist for HarmonyOS. |
| D7 | Figures 2–3 bucket boundaries | Only the printed bucket labels are given | Half-open intervals: Fig. 2 `[0,10) [10,30) [30,50) [50,100) [100,500]`; Fig. 3 `[0,3) [3,5) [5,10) [10,50]` | These boundaries reproduce all 39 printed percentages exactly; inclusive lower bounds do not. |
| D8 | HarmonyOS numeric fields | Not discussed; the paper does not describe the released file format | Some HarmonyOS `Involved Functions` values are strings, including the capped `"20+"`; the integer prefix is parsed | The cap only affects the open-ended last bucket, so no reported percentage changes. |
| D9 | Number of runs | The paper reports a single deterministic analysis | Three runs of the full pipeline, with every output hashed | The course requires mean ± standard deviation over at least three runs; the analysis has no randomness, so the standard deviation is 0.00. This is shown in `results/logs/determinism.md`. |
| D10 | Implementation | The authors' analysis code is not released | An independent implementation written for this replication (`scripts/`, standard library only) | Required for a replication. The 600/603 exact matches are on values this implementation computed itself. |
| D11 | Scale | 1,500 defects | All 1,500 released defects, no sampling | The released dataset supports the full scale, so no reduced scale was needed. |
| D12 | Environment | Not reported | Windows 11, CPython 3.14, standard library only; Docker image based on `python:3.12.7-slim` | Pinning the interpreter makes the analysis reproducible on a clean machine. The exact run is recorded in `results/summary.json`. |
| D13 | Figure 4d text vs heatmap | The text attributes −0.11 to “Linux and Android”, while the heatmap places −0.11 at Android–HarmonyOS | The heatmap values are used as reference | The paper is inconsistent here; see `DISCREPANCIES.md`. The transcription follows the figure, as stated in `data/paper/README.md`. |
