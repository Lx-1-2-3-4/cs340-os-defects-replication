# Deviations from the paper's setup

The course report asks for a deviations table. This is that table, kept next to
the code so it stays current.

| ID | Item | Paper's setting | Setting used here | Reason |
| --- | --- | --- | --- | --- |
| D1 | Labelling step | 1,500 defects labelled by two annotators; disagreements resolved with a third senior researcher; Cohen's kappa 0.8–1.0 | The authors' released labels are used as they are | The raw candidate corpus, annotator assignments and protocol are not released, and re-labelling 1,500 patches is out of scope. This is the main limitation (see `docs/CLAIMS.md`). |
| D2 | Data collection | Crawlers over Android Security Bulletins, the Linux bug tracker and Huawei's HarmonyOS trackers; per-system windows 2023.04–2025.06 (Linux), 2023.05–2025.06 (HarmonyOS), 2023.05–2025.12 (Android); initial reports 32,249 / 712 / 1,750 (Table I) | Dashboard snapshot retrieved 2026-11-05 (`data/PROVENANCE.json`, SHA-256 of page and files recorded) | The dashboard is the only full-scale public source. Table I's initial-report counts and the collection funnel cannot be rebuilt from the released records and are not verified. |
| D3 | Code-element percentages (last Table II panel) | Not stated; `Code Level` is multi-label | A defect contributes one count to every tag in its comma-separated label; percentage = count / 500 | This is the only rule that reproduces all 36 code-element percentages exactly. |
| D4 | Figure 4c category handling | Not stated | Categories that are zero for **both** systems of a pair are dropped before computing Spearman's rho | Needed to reproduce the printed 0.38 for Android–HarmonyOS; without dropping, the value is 0.61. Other panels are unaffected. |
| D5 | Figure 4d "Overall" panel | Not specified in the paper | Concatenate the 21 categories of panels (a)–(c), apply rule D4, compute Spearman's rho | The rule behind the printed values is unknown; five candidate rules are compared in `docs/DISCREPANCIES.md`, and none reproduces the panel. |
| D6 | HarmonyOS missing severity | Table II reports HarmonyOS "Undecided" 1.20% | The six HarmonyOS records labelled `Unknown` are mapped to `Undecided` | Reproduces 1.20% exactly (6/500). Without the mapping the category would be missing. |
| D7 | Figures 2–3 bucket boundaries | Only the printed bucket labels are given | Half-open intervals: Fig. 2 `[0,10) [10,30) [30,50) [50,100) [100,500]`; Fig. 3 `[0,3) [3,5) [5,10) [10,50]` | These boundaries reproduce all 39 printed percentages exactly; other conventions (for example inclusive lower bounds) do not. |
| D8 | HarmonyOS numeric fields | Not applicable; the paper does not discuss the released file format | Some HarmonyOS `Involved Functions` values are strings, including a capped `"20+"`; the integer prefix is parsed | The cap only affects the open-ended last bucket, so bucket membership and all reported percentages are unchanged. |
| D9 | Repeated runs | The paper reports a single deterministic analysis | Three identical runs of the pipeline | The course asks for mean ± standard deviation over at least three runs. The recomputation has no randomness, so the standard deviation is 0.00; this is reported in `results/logs/determinism.txt`. |
| D10 | Implementation | The authors' analysis code is not released | Our own standard-library implementation (`scripts/`) | Required for a replication. It is checked by the 600/603 exact matches on outputs that we computed independently. |
| D11 | Scale | 1,500 defects across three systems | All 1,500 released defects, no reduction | The released dataset supports the full scale. |
| D12 | Environment | Not reported | Local: Windows 11, Python 3.14.6. Docker: `python:3.12.7-slim`, standard library only | The pipeline is pure data analysis. The container pins the interpreter so the environment can be reproduced; exact versions are in each run's `results/summary.json` and log. |
| D13 | Figure 4d text vs figure | Text says the largest absolute coefficient is −0.11 "between Linux and Android"; the heatmap places −0.11 at Android–HarmonyOS | We use the figure values | The paper is inconsistent here; see `docs/DISCREPANCIES.md`. |
